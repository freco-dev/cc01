## Kontekst

`ARCHITECTURE.md` v1.0 butun boshqaruv mantiqini Go'dagi Control Plane ichiga joylashtirgan edi:
`cc01-idp` foydalanuvchi autentifikatsiyasini ham, node sertifikatlarini ham bajarishi kutilgan.

Ayni paytda repozitoriyda `access-server/` — .NET 10 / Clean Architecture skeleti mavjud,
`User`, `UserToken`, `Entity` domen sinflari yozilgan. Hujjatlarda bu komponent umuman zikr
qilinmagan, ya'ni hujjat va kod o'rtasida ochiq uzilish bor edi.

Hal qilinishi kerak bo'lgan savol: hisob/tarif/billing mantiqi qayerda yashaydi?

## Ko'rib chiqilgan variantlar

### A. Hammasi Go'da (`cc01-idp` ichida)

- ➕ Bitta til, bitta build, bitta protobuf, bitta CI.
- ➕ `DEV_SPEC.md` monorepo strukturasi o'zgarishsiz qoladi.
- ➖ Mavjud .NET ishi tashlanadi.
- ➖ CRUD va billing domeni Raft KV bilan bir servisga tiqiladi — ular butunlay boshqa
  konsistentlik va reliz talablariga ega.
- ➖ Dashboard uchun tez-tez reliz qilinadigan kod data plane bilan bir binarda bo'ladi.

### B. Hammasi .NET'da

- ➖ eBPF, XDP, TUN, Noise, netlink ekotizimi Go va C'da. .NET'da bu yo'l amalda yopiq.
- Darhol rad etildi.

### C. Ajratish: AP = .NET, CP = Go  ✅ **tanlandi**

- ➕ Har bir domen o'z ekotizimida: tarmoq/kernel — Go va C, hisob/billing — .NET + EF Core.
- ➕ Mavjud `access-server` skeleti saqlanadi va rivojlanadi.
- ➕ Kompromis radiusi kichrayadi: AP buzilsa node private kalitlariga, sertifikatlarga va
  mavjud sessiyalarga ta'sir qilmaydi.
- ➕ Mustaqil reliz kadensiyasi: dashboard tez, data plane ehtiyotkorlik bilan.
- ➖ Ikki toolchain, ikki CI pipeline, ikki deploy yo'li.
- ➖ Kontrakt endi tarmoq chegarasi — versiyalash va orqaga moslik intizomi talab qilinadi.

## Qaror

**Variant C.** `access-server` .NET'da alohida servis sifatida rivojlanadi va **Account Plane (AP)**
deb ataladi. Chegara quyidagicha:

| AP (`access-server`, .NET) | CP (Go) |
| --- | --- |
| Odamga qaragan: hisob, login, OAuth | Mashinaga qaragan: node, daemon, edge |
| API token, subdomain va domen egaligi | Node sertifikati, IPAM, NetworkMap, policy |
| Tarif, kvota qiymatlari, billing, usage | Kvotani **majburlash** (edge'da) |
| PostgreSQL (relyatsion) | Raft KV (kuchli konsistentlik) |

**Invariant:** AP data plane yo'lida turmaydi. Tunnel ochilgandan keyin AP ishtiroki tugaydi;
AP o'chsa oqayotgan trafik davom etadi.

## Oqibatlar

**Ijobiy**

- Hujjat va kod o'rtasidagi uzilish yopiladi.
- AP va CP mustaqil miqyoslanadi va relizlanadi.
- Xavfsizlik chegarasi aniq: hisob bazasi sizib chiqsa kriptografik material tegilmaydi.

**Salbiy / narxi**

- CI matritsasi kengayadi: Go (lint, test, eBPF verifier) + .NET (build, test, EF migratsiya).
- Kontrakt buzilishi endi kompilyatsiya xatosi emas, runtime xatosi — shuning uchun kontrakt
  testlari (`test/contract/`) majburiy.
- Ikki xil observability sozlash kerak; ikkalasi ham OpenTelemetry'ga chiqaradi.

**Kuzatiladigan risk**

Agar 6 oy ichida AP ↔ CP chegarasi "chatty" bo'lib qolsa (bir amal uchun bir nechta sinxron
chaqiruv), qaror qayta ko'rib chiqiladi — o'sha holatda AP mas'uliyatining bir qismi CP'ga
ko'chirilishi mumkin.
